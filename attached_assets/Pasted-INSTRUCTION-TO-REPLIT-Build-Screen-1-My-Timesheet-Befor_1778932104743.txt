COMPONENT: TimesheetRow
══════════════════════════════════════════════

Props: rowData, rowIndex, weekDates[7], onCellChange, onCellFocus, onProjectChange, onTaskChange, onDelete, isReadOnly

─── Project Dropdown ───
Source: GET /api/time/assigned-projects
First option (pinned, styled differently): "📅 Leave" — value: '__LEAVE__'
Remaining options: assigned active projects sorted alphabetically
If a project has a fixed-bid contract: show "(Fixed-Bid)" suffix in muted text

On select:
- Clear task dropdown and all hour cells for this row
- If '__LEAVE__' selected: set isLeave=true on row, fetch leave types for task dropdown

─── Task/Leave Type Dropdown ───
Disabled until project is selected.
If normal project: GET /api/time/assigned-tasks/:projectId filtered to active tasks
If Leave: GET /api/time/leave-types
Show below task name (in muted text): "Budget: [X] hrs" if task.budget_hours is set

On select: call validateExceptionalEffort check immediately with current row hours

─── Day Cells (7 cells, Mon–Sun) ───
Input type: number, min: 0, max: 24, step: 0.25
Accept decimal values.
Width: narrow (enough for 4 digits + decimal, e.g. "8.25")

Disabled state (render as greyed, non-interactive) when:
- Row is read-only (timesheet is Submitted/Approved)
- Cell's date falls in a closed financial period
- Cell's date is beyond the future date buffer (beyond Sunday of current week)

On keypress: allow only digits, one decimal point, and backspace. Block all other characters.

On blur:
1. Parse value. If not a valid positive number: reset to 0, show cell-level error
2. Call validateEffortIncrement → show cell-level increment error with suggestion
3. Call validateDailyHoursCap → if exceeded, highlight day column total red, show tooltip
4. Recalculate row total
5. Call validateExceptionalEffort → if exceptional flag triggered, show ExceptionalPanel
6. Save to local browser localStorage as draft auto-save (key: "bns_timesheet_draft_{userId}_{weekStart}")
7. Trigger onCellChange to update parent state and Summary Bar

Visual cues:
- Cell with a description: small blue dot in top-right corner of cell
- Exceptional row: amber left border on entire row
- Rejected row: red left border, "(Rejected)" badge in project column

─── Row Total ───
Auto-calculated sum of 7 cells. Right-aligned. Read-only display.
If row total > task.budget_hours: show total in amber text + ⚠ icon with tooltip "Exceeds task allocation of [X] hrs"
If row total = 0 and timesheet is Draft: show "0.00" in muted grey

─── Billable Category Badge ───
Small badge showing current billable_category.
Auto-set from task selection (cannot be changed by Consultant).
Authorized_Approver sees a small pencil icon to override (opens confirmation dialog).

─── Delete Button ───
Small × icon at far right.
Visible only when row is in Draft status.
On click: confirmation: "Remove this row? Hours entered will be lost." → on confirm: remove row from state (do not call API until next save)

══════════════════════════════════════════════
ACTION BAR (sticky bottom of page, always visible)
══════════════════════════════════════════════

Show buttons based on pageStatus:

pageStatus = 'Empty' or 'Draft':
  [Save Draft] (secondary) | [Submit] (primary)
  Submit is greyed if: validation errors exist / exceptional rows without justification / prior rejected week unresolved

pageStatus = 'Submitted':
  [Recall Timesheet] (secondary, outline)
  Note below: "Your timesheet is with your approver. Recall to make changes."

pageStatus = 'Approved':
  No action buttons.
  Banner: "✅ Approved — This timesheet has been approved and is locked."

pageStatus = 'Rejected' (some entries rejected, some submitted/approved):
  [Fix & Resubmit] (primary) — scrolls to rejected rows
  Note: "Some entries need correction. Edit the highlighted rows and resubmit."

pageStatus = 'Mixed':
  [Submit Remaining Drafts] | [Recall All]

─── Save Draft behavior ───
Call POST /api/time/entries for each new row (no ID yet).
Call PATCH /api/time/entries/:id for rows with existing IDs.
Process row by row — if one row fails validation, save all others and highlight the failed row.
Show success toast: "Draft saved." or "X rows saved, Y rows need correction."

─── Submit behavior ───
Pre-submit client checks (in order):
1. Total hours > 0 across all rows (V-12)
2. No day total > 24 (V-04)
3. No increment violations (V-03)
4. All exceptional rows have justification (V-06)
5. Prior week has no Draft entries (V-13) — show banner if failed
If all pass: call POST /api/time/entries/submit
On 422: display field-level errors returned from server
On success: update pageStatus to 'Submitted', show toast "Timesheet submitted for approval."

─── Recall behavior ───
Confirmation dialog: "Recall this timesheet? It will move back to Draft and your approver will be notified."
[Cancel] | [Recall]
On confirm: call POST /api/time/entries/:id/recall (using any entry ID from the week)
On success: status reverts to Draft, grid becomes editable.

LOCAL AUTO-SAVE

Key: "bns_timesheet_{userId}_{weekStart}"

On page load: if localStorage key exists for current week and user:
- Show banner: "You have unsaved changes from [timestamp]. [Restore] [Dismiss]"
- Restore: populate grid from localStorage data
- Dismiss: clear localStorage key, start fresh

Clear localStorage key after successful Save Draft or Submit.
